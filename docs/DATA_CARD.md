# Data card — Vitera synthetic corpus v0.1

**Everything in this corpus is synthetic. No real patient data was used, seen or
approximated from a real record.** It is generated from published aggregate
statistics about Indonesian BPJS inpatient claims, not from any hospital's data.

- **Produced by:** `make data` → `vitera.generator.cli`
- **Manifest:** `data/generated/MANIFEST.json` (seed, per-stage seeds, config and reference file hashes)
- **Seed:** `20260731` · generator stage `628083628` · injection stage `628084338`
- **Size:** 4,000 episodes — 2,668 train / 1,332 test
- **Language:** Bahasa Indonesia
- **Licence:** to be released with the paper after the competition
- **`domain_verified`: `false`** — see *Verification status*, below. **This is the most important field in the manifest.**

---

## 1. What an episode is

A **dated sequence of events**, not a snapshot. Collapsing the sequence at
`day = discharge` reproduces the flat episode exactly — `Episode.at_day` and a
test in `tests/test_generator.py` enforce it. That invariant is what makes
concurrent monitoring the discharge pipeline invoked N times rather than a
second system.

Each episode carries:

| Field | Contents |
|---|---|
| `primary_dx` | ICD-10 code drawn from an 18-group CBG reference set |
| `secondary_dx` | comorbidities, **each with two timestamps** (below) |
| `procedures` | ICD-9-CM, present only for surgical groups |
| `events` | dated labs, meds, vitals, procedures |
| `documents` | `berkas_klaim` (day 0), one `cppt_hari_N` per day, `resume_medis` (discharge) |
| `discharge_day` | length of stay |

Mean 10.0 documents per episode; mean resume medis 252 characters; mean LOS 6.99 days.

### The two timestamps

```
signal_day       when treatment / labs / meds first make the diagnosis visible
documented_day   when it appears in the notes — or null
```

`documented_day = null` is the undercoding case. The window between the two is
the interval Vitera claims to operate in, and it is what `detection_lead_time`
measures. **Signals always appear in the CPPT; documentation appears in the
resume medis only if `documented_day` is set.** A test asserts that for every
undocumented diagnosis, its lab and medication signals are present in the record
while its code is absent from the discharge summary.

## 2. Two ground-truth labels, deliberately separate

Conflating these would make the fairness analysis unattributable, so they are
generated by different mechanisms and labelled independently:

| Label | What it is | Source |
|---|---|---|
| **Site quality** | sparse documentation — a property of the hospital | `config/sites.yaml` `doc_quality` |
| **Injected defect** | a wrong or missing code — a coding error | `config/defects.yaml` rates |

Undercoding therefore appears **even in defect-free episodes**, because it is a
documentation phenomenon rather than a coding one. `clean_claim()` codes only
documented diagnoses.

### Configured vs. realised defect rates

An injector returns `None` when the episode cannot carry that defect. These
differ, sometimes a lot, and the realised column is what the corpus actually
contains:

| | D1 | D2 | D3 | D4 | D5 | D6 | D7 | D8 |
|---|---|---|---|---|---|---|---|---|
| configured | 0.041 | 0.100 | 0.086 | 0.240 | 0.122 | 0.050 | 0.067 | 0.039 |
| **realised** | 0.039 | 0.046 | 0.087 | 0.067 | 0.061 | **0.006** | 0.071 | 0.040 |

**D6 realises at one eighth of its configured rate** because only 3 of 18 CBG
groups carry a procedure. **D4 realises at one quarter** because it needs an
undocumented *major* comorbidity. Any per-class result on D6 is small-sample.
Mean 5.35 of 8 classes are eligible per episode.

|---|---|---|

| B | 1,334 | 0.661 |
| C | 1,332 | 0.743 |

**Class D appears only in the test split** — if the model degrades on the
lowest-resourced facility class it has never seen, that is the fairness finding,
not a bug to be trained away.

## 5. How negatives were made

**By changing codes, never by regenerating text.** Regenerated text carries
stylistic fingerprints and a model learns those instead of clinical reasoning.
A test asserts document text is byte-identical before and after injection.

`D1` and `D5` remove pages from the claim file — removal, not rewriting.

### Leakage check (`make leakage`)

A TF-IDF + logistic-regression classifier reading **only** the clinical
narrative, no codes, trying to predict the defect label. Chance is 0.500.

| class | n test | positive rate | AUC | 95% CI | verdict |
|---|---|---|---|---|---|
| D2 | 355 | 0.079 | 0.590 | [0.479, 0.693] | at chance |
| D3 | 961 | 0.074 | 0.464 | [0.400, 0.535] | at chance |
| D4 | 255 | 0.267 | 0.474 | [0.400, 0.558] | at chance |
| D5 | 365 | 0.104 | 0.555 | [0.460, 0.654] | at chance |
| D6 | 161 | 0.037 | 0.664 | [0.463, 0.863] | at chance |
| D7 | 958 | 0.071 | 0.495 | [0.425, 0.568] | at chance |
| **D1** | 928 | 0.041 | **0.909** | [0.860, 0.947] | **leaks — expected** |

D1 removes the resume medis, so the text genuinely differs. That is the defect
itself, not a fingerprint, and a rules engine is meant to catch it trivially.

**The test is run per defect class, conditioned on eligibility.** This matters
and we got it wrong twice. Aggregating classes failed at AUC 0.637, then 0.647
— not because of a stylistic fingerprint, but because episodes *eligible* for a
defect differ from ineligible ones in ways visible in the narrative (D6 needs a
procedure; D4 needs an undocumented major comorbidity), and being eligible for
more classes raises P(any defect). The classifier was reading composition, not
mutation. Only per-class conditioning on a shared eligible pool removes the
confound. `eligible_for` is recorded on every row so downstream evaluation can
condition the same way.

**Caveat: D6 and D2 are underpowered.** D6 has 161 test rows and 6 positives; a
CI of [0.463, 0.863] means "not shown to leak", not "shown not to leak".

## 6. Verification status

**`domain_verified: false`.** Every ICD-10 code, ICD-9-CM code, INA-CBG code,
severity weight, length-of-stay range, lab threshold and **every rupiah tariff**
in `data/reference/*.yaml` is a plausible placeholder written without access to
a real INA-CBG tariff table. The generator emits `UnverifiedReferenceWarning` on
every run and stamps the flag into the manifest.

**No figure derived from this corpus may enter the paper or the deck until
`data/reference/*.yaml` has been reviewed by the domain owner and `verified` set
to `true`.** This applies with particular force to any monetary figure: the
grouper is authoritative for tariff, and it is currently authoritative over
invented numbers.

## 7. Limitations

1. **Synthetic throughout.** No practising-coder validation, no real BPJS
   pend-reason data. External validity is untested and, at this stage, untestable.
2. **`detection_lead_time` is partly an artifact of our own sampling.** We chose
   `signal_day` and `documented_day`; no published Indonesian study reports
   documentation timing relative to clinical signal. Every report of the metric
   must be labelled *under stated generator assumptions*, and bucket 11 runs a
   sensitivity sweep over the gap parameter. If the lead-time claim depends on
   that choice, the claim is weakened rather than the parameter tuned.
3. **The hospitals are synthetic too**, so hospital-level holdout controls for
   site variation *within our model of site variation*, not within reality.
4. **Severity III is rare (0.9%)** and comorbidity prevalences were set to make
   it reachable at all. Any severity-III result is small-sample.
5. **Eight defect classes are our construction**, assembled from study
   categories. BPJS publishes no pend-reason taxonomy, so the classes are not
   the payer's own.
6. **Text is templated**, so linguistic variety is far below a real resume
   medis. This makes the retrieval task easier than reality and the leakage
   check harder to pass — the first inflates results, the second is a genuine
   control.
7. **D6 and D2 realise at low rates**, so per-class conclusions about them are
   underpowered.

---

## 8. Intended and unintended use

**Intended.** Benchmarking pre-submission claim verification for Indonesian
inpatient BPJS episodes; studying detection lead time under concurrent
monitoring; as a public benchmark once released.

**Not intended.** Training anything that will touch a real claim without
re-validation on real data; estimating real tariffs or revenue; any inference
about a named hospital, region or clinician. The corpus contains no real
entities to infer about, and treating it as if it did would be an error rather
than a privacy breach.

---

## 9. Reproduction

```bash
make data      # rebuilds the corpus from the seed in the manifest
make leakage   # re-runs the per-class leakage check
make arm-a     # rules-only baseline against the frozen test split
```

Byte-identical output requires matching `config_hashes` and `reference_hashes`
from the manifest. A changed hash means a changed corpus, and any figure
produced from the old one must be regenerated.
